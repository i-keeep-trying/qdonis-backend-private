## Topology-Specific Rules: Single-Phase Active Front End (AFE) Rectifier

To ensure a single-phase Active Front End (AFE) rectifier simulates correctly, stabilizes quickly, and produces clean sinusoidal currents, adhere to the following power stage, control loop, and SPICE syntax rules:

### 1. Power Stage & Component Ratings

* **Size the DC Link Capacitor for Double-Frequency Ripple**: Single-phase systems experience pulsating power at twice the line frequency (100Hz or 120Hz). Capacitors in the microfarad range are too small and will cause massive voltage swings. Use millifarad values (e.g., 1 mF to 3 mF for 3kW–5kW loads) to properly buffer the energy and keep voltage ripple within 5%.
* **Ensure High Breakdown Voltages (`Bv`)**: In your `.model` definitions for diodes and MOSFETs, the reverse breakdown voltage (`Bv`) must comfortably exceed your target DC bus voltage (e.g., use 700V–800V for a 400V–450V bus). If `Bv` is too low (e.g., SPICE default 100V), the pre-charged DC link will cause instant avalanche breakdown at $t=0$, drawing massive current spikes (500A+), clamping the voltage, and crashing the solver.

### 2. Control Loop Tuning & Filters

* **Prevent Leaky PI Integrators**: SPICE requires a DC path to ground, often forcing you to place a dummy resistor in parallel with the PI controller's integration capacitor. This resistor must be strictly parasitic (1 MΩ to 10 MΩ). A low value (e.g., 150 Ω) bleeds off the charge, destroying the controller's DC gain and causing a permanent steady-state voltage error.
* **Block 100Hz Feedback (Magnitude Filter)**: The DC bus will always have some 100Hz/120Hz ripple. If the low-pass filter on the voltage PI output is too fast, this ripple passes into the magnitude command. Multiplying a 50Hz grid reference by a 100Hz ripple generates 3rd harmonic distortion (a "double-hump" M-shape in the AC current). Set this filter's cutoff below 5Hz (e.g., 10µF to 100µF with a 1 kΩ resistor).
* **Block Switching Noise (PWM Filter)**: The current control signal must pass the 50Hz grid dynamics but completely block high-frequency (e.g., 100kHz) switching noise. Size this RC filter for a 3kHz–5kHz cutoff (e.g., 47nF and 1 kΩ).
* **Power-Level Specific PI Tuning**: Your voltage loop proportional ($K_p$) and integral ($K_i$) gains must be scaled based on the load power ("plant"). For example, a 5kW 450V system might use $K_i = 0.002$ and $K_p = 0.1$, while a 3kW 400V system requires drastically slashed integral gain (e.g., $K_i = 0.0005$) and increased proportional gain (e.g., $K_p = 0.25$) to prevent control loop hunting. Carefully tune these parameters based on your specific input/output voltages and power levels.

### 3. SPICE Syntax & Solver Stability

* **Perfect PWM Syntax (No Dead Switches)**: When defining behavioral sources for gate drive signals (e.g., `B_A_BOT`, `B_B_BOT`), ensure perfect syntax. **Do not use illegal line breaks, avoid stray hyphens (`-`), and always include proper multiplication operators (`*`)**. Example: `expression: 7.5 * (1 + tanh((v(n_ctrl) - v(n_tri) - 0.2)*100))`. Incorrect syntax will cause SPICE to discard the PWM logic entirely, leaving all MOSFETs permanently turned off.
* **Use Explicit Node Names for Feedback**: Schematic capture tools often auto-generate sequential numerical node names (e.g., `n18`, `n25`). If your behavioral control equations (`B_...`) expect text labels (`v(n_err)`, `v(n_ctrl)`), the sensors will disconnect from the PWM logic, and the circuit will run as an unregulated boost converter. Explicitly place text net-labels (`n_err`, `n_ctrl`, `n_duty_A_top`, `n_duty_B_top`, `n_DC_BUS`, `n_tri`, `n_mag_flt`, `n_ref`, `n_iact`) on all feedback paths in your schematic.
* **Parameterize Grid and Target Values**: Use `.param` variables at the top of the netlist (e.g., `.param V_TARGET=400 V_PEAK=325.27` or `.param V_TARGET=450 V_PEAK=339.4`) rather than hardcoding values inside your behavioral equations. This prevents scaling errors when adapting the design for different power levels or grid voltages.
* **Never Force 0V on Switching Nodes**: Only use `.ic` (initial condition) statements to pre-charge bulk energy storage components like the DC link capacitor (`V(n_DC_BUS)=V_TARGET`). Forcing a high-frequency switching node (like an H-bridge midpoint `n_SW_A` or `n_SW_B`) to 0V will violently clash with the controller's immediate command to turn a top MOSFET on, creating infinite $dV/dt$ current spikes that crash the solver with "timestep too small".
* **Calculate Accurate Steady-State Initial Conditions**: To avoid massive startup transients that take hundreds of milliseconds to settle, initialize *both* your PI integration node and your magnitude filter node to the exact mathematical expected steady-state AC peak current. Calculate this as $I_{peak} = \sqrt{2} \cdot \frac{P_{load}}{V_{rms}}$. For example, for a 5kW 240V system, initialize to $\approx 29.5A$. For a 3kW 230V system, initialize to $\approx 18.44A$. The command should look like `.ic V(n_DC_BUS)=400 V(n_INT)=18.44 V(n_mag_flt)=18.44`.
* **Run Adequate Simulation Times**: A 50ms transient analysis is often too short to verify steady-state operation in a 50Hz system. Run the simulation for at least 150ms (`tstop: 0.15`) to ensure all startup transients have settled, and restrict your `.meas` commands to the final 10ms (e.g., `from 0.14 to 0.15`) for accurate RMS and average readings.
