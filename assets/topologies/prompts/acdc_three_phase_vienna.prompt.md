## Topology-Specific Rules: Three-Phase Vienna Rectifier
- **Control scaling is automatic (OVERRIDES the items below)**: The input voltage is the grid line-to-line RMS value. The application writes the grid source amplitudes/frequency, every behavioural control expression (current-reference normalisation, DC-bus target, duty feed-forward, current limit), the integrator and DC-capacitor initial conditions and the load (`Vout^2 / Pout`). Do NOT emit expressions for B_* sources. Focus on the boost inductors, DC-link capacitors and semiconductor ratings.
- **Grid Voltage and Current Reference Scaling**: The reference netlist uses a specific phase peak voltage in the AC sources (e.g., `170.0` for 208Vrms line-to-line) and in the current shaping references (`B_Iref_A`, `B_Iref_B`, `B_Iref_C`). 
  - If the requested input voltage (`Vin`) changes, you MUST calculate the new peak phase voltage $V_{peak} = (V_{in(L-L)} / \sqrt{3}) \times \sqrt{2}$. 
  - You MUST update the `amplitude` parameter of `V_AC_A`, `V_AC_B`, and `V_AC_C` to this new $V_{peak}$.
  - You MUST update the denominator in the expressions for `B_Iref_A`, `B_Iref_B`, and `B_Iref_C` to match this exact $V_{peak}$ value (e.g. `expression: V(i_mag) * abs(V(v_a_grid)) / V_peak`). Do not blindly copy the old scaling factor.
- **Node Naming and Switch Wiring**: The custom named nets (`n_A_raw`, `n_neutral`, `v_dc_tot`, etc.) MUST be preserved if you emit the base logic equations. Do not remove the named nets from the `nets` section. Make absolutely sure you do not invent node names that aren't defined in the nets.
- **Switches**: The topology uses explicitly defined `switch` components (`S_A`, `S_B`, `S_C`). Ensure they are correctly wired to the inductor outputs and GND. Do not replace them with custom_spice lines unless explicitly directed.
- **Integrator Initial Condition**: The base template includes a hardcoded integrator starting condition for a 15kW system (e.g. `ic: "v(int_v_error)=..."`). You MUST dynamically recalculate and explicitly emit the correct starting condition (`ic`) for the requested voltage and power. Do NOT blindly copy the 15kW reference.
- **Filter Parameters**: You MUST recalculate and update all filter parameters (inductors, capacitors) to suit the newly requested input/output voltage and power rating. Do not blindly copy the reference filter values.
- **Fatal Node-Naming Disconnect**: You MUST NOT auto-generate numerical node names (e.g., 
25) for your behavioral sources if the internal equations (e.g., ='800 - V(v_dc_tot)') refer to semantic names like _dc_tot. You must ensure that the equations strictly reference the actual nodes present in the netlist.
- **Dynamic Voltage Targets**: You MUST NOT hardcode the 800 value in the B_VERR equation (or similar error blocks) (e.g., ='800 - V(v_dc_tot)'). You MUST dynamically replace this value with the requested target DC output voltage.
- **Duty Cycle Feedforward Math**: You MUST update the duty cycle feedforward term (e.g. inside the control sources) to use exactly HALF the requested DC bus voltage in the denominator. For example, if the requested Vout is 600V, the expression MUST use 300 (e.g., bs(V(v_a_grid))/300), not 400.
- **Current Sensing Filter Cutoff**: You MUST keep the current sensing filter resistor (e.g., R_fA, R_fB, R_fC) strictly at \text{k}\Omega$ (and \text{nF}$ capacitors) to maintain a ~1.6kHz cutoff. Do not increase it to \text{k}\Omega$, as this drops the cutoff to 160Hz and causes severe grid tracking distortion.
